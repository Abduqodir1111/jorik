# Jorik — единый inbox и мини-CRM

Рабочее пространство для двух Telegram-аккаунтов и двух Instagram-аккаунтов:
переписка, быстрые ответы, черновики, заказы, доставка и самовывоз.

**Стек:** React, TypeScript, Vite, Fastify, SQLite, SSE; Telegram MTProto
через teleproto и Instagram Messaging API через Meta.

## Локальный запуск

Нужны Node.js **24 LTS** (версия указана в `.nvmrc`) и npm.

```sh
npm ci
cp .env.example .env
npm run owner
npm run seed
npm run dev
```

Откройте http://127.0.0.1:5173. По умолчанию включён демонстрационный режим:
примеры сообщений остаются локальными и не отправляются в мессенджеры.
Команда `owner` создаёт пароль владельца; сохраните его в менеджере паролей.
Не копируйте `.env.example` поверх уже настроенного `.env`.

Если API-порт занят, можно запустить `PORT=5311 npm run dev` — Vite направит
запросы к этому порту. Сервер разработки привязан к loopback.

```sh
npm test
npm run typecheck
npm run build
npm start
```

После сборки `npm start` обслуживает интерфейс и API на одном порту
(по умолчанию http://127.0.0.1:3001).

## Возможности

- Фильтры платформы, аккаунта и непрочитанных; поиск по сохранённой переписке.
- По умолчанию 50 последних диалогов каждого аккаунта; полный сохранённый
  список доступен отдельной кнопкой и через поиск.
- История и статусы обновляются через SSE. Фото и видео загружаются через
  авторизованный серверный маршрут без передачи токенов в браузер.
- Отдельные черновики и очередь отправки, до 100 динамических шаблонов быстрых ответов.
- Enter — отправить, Shift+Enter — новая строка, `/` — шаблоны,
  Alt+↑↓ — переключение чатов, Ctrl+1–9 — отправка первых девяти шаблонов.
- Заказы из чата и ручной приём, редактирование, история по телефону,
  доставка/самовывоз и экспорт Excel для курьера.
- Компактная форма заказа остаётся открытой во время работы с чатом, включая
  переключение диалогов. Маска +998, история по точному номеру и подстановка
  последнего адреса ускоряют оформление; сумма должна быть больше нуля.
  На телефоне форма расположена снизу, поля доступны с прокруткой.
- Светлая/тёмная тема, размер текста и звук сохраняются в браузере;
  быстрые ответы и данные заказов — на сервере.

## Реальные интеграции

Настройте собственные значения в `.env` по шаблону `.env.example`, затем
используйте `APP_MODE=real`. Demo и real хранятся в разных SQLite-файлах.

### Telegram

Нужны `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и
`INTEGRATION_ENCRYPTION_KEY` — 32 случайных байта в виде 64 hex-символов.
Вход каждого аккаунта выполняется в «Настройки» → «Аккаунты и подключения»: номер, код и пароль
двухэтапной проверки, если он включён. Сессии хранятся в зашифрованном виде.

Команда `npm run telegram:prepare` помогает подготовить локальную конфигурацию;
перед её использованием остановите приложение. **Не запускайте одну Telegram-
сессию одновременно на нескольких серверах.**

### Instagram

Для каждого магазина нужен собственный Page access token и связанный
профессиональный Instagram-аккаунт. Права и доступ приложения должны быть
разрешены Meta для используемых аккаунтов.

Укажите `PUBLIC_BASE_URL` с действующим HTTPS, `META_SELLER_APP_SECRET` и
`META_WEBHOOK_VERIFY_TOKEN`. Callback: `https://<ваш-домен>/webhooks/instagram`.
Подпись входящих запросов проверяется сервером. Для приложения нужны события
`messages`, `messaging_seen`, `messaging_postbacks`, `standby`; подписки страниц
и аккаунтов настраиваются отдельно с поддерживаемыми Meta именами полей.

Приём работает через вебхуки. Кнопка импорта загружает до 50 последних бесед;
постоянного опроса архива нет. Стандартное окно ответа Instagram — 24 часа
после сообщения клиента. API может не передавать отдельные вложения и статусы.

Ответы магазина из официальных приложений учитываются при сбросе предыдущих
непрочитанных. Клиентское прочтение нашего ответа не сбрасывает входящие.
Telegram также обрабатывает прочтение с других устройств. Для Instagram
прочтение продавцом без ответа зависит от доступных событий и данных Meta:
отсутствие `unread_count` никогда не считается нулём.

### Восстановление после перебоя сети

Telegram повторяет подключение с сохранённой сессией: через 5, 10, 20,
40 секунд, затем раз в минуту. Зависший клиент заменяется; обычные RPC-запросы
ограничены 30 секундами. `FloodWait` провайдера соблюдается. Отозванная сессия
требует повторного входа и останавливает автоматические попытки.

В режиме вебхуков Instagram раз в минуту проверяется доступ к API. После
сетевой ошибки проверка повторяется с таким же постепенным ожиданием;
недействительный токен или права требуют обновления подключения. После
перерыва выполняется ограниченная догрузка: до 50 последних бесед, до 30
сообщений каждой беседы. Постоянного опроса архива нет. Сетевые ошибки догрузки
повторяются не более трёх раз за цикл восстановления. Полнота старой истории
зависит от доступных данных и разрешений Meta.

Повторный импорт сопоставляет ID сообщений и сохраняет границы прочтения.
Автовосстановление не переотправляет сообщения со статусом «Результат неизвестен».
Журнал `integration_recovery` содержит аккаунт, стадию, код ошибки и задержку;
токены, коды входа и содержимое сообщений в эти записи не включаются.

## Хранение и развёртывание

`DATA_DIR` содержит базу, вложения и зашифрованные сессии. Токены и ключ
шифрования задаются вне образа. Сохраняйте данные и ключ отдельно от кода;
обновление приложения не должно заменять рабочую базу локальным снимком.
Перед миграциями делайте согласованную SQLite-копию.

```sh
npm run backup
```

Для контейнерного запуска есть `Dockerfile`. Порт приложения — 3001,
каталог постоянных данных — `/app/data`. Передавайте конфигурацию через
переменные окружения, подключайте постоянный том, используйте HTTPS reverse
proxy и задайте корректный `PUBLIC_BASE_URL`. Учтите, что entrypoint под root
назначает владельцем выделенного каталога данных пользователя `node`;
не подключайте к `/app/data` чужие общие каталоги.

Пароль владельца хранится как scrypt-хеш; сессии — как хеши токенов.
Медиа и API требуют входа. При публичном HTTPS cookie использует
Secure/HttpOnly/SameSite. Вход поддерживает запоминание устройства.
`LOCAL_TEST_NO_PASSWORD` и `LOCAL_TEST_NO_RATE_LIMIT` оставляйте `false`
для рабочего сервера.

## Состав репозитория

- `src/` — интерфейс и адаптивное оформление.
- `server/` — API, адаптеры, очередь отправки и хранение.
- `shared/` — общие типы и правила заказов.
- `migrations/` — версионируемые миграции SQLite.
- `tests/` — регрессионные проверки.
- `public/` — необходимые ресурсы интерфейса и страницы политики.
- `scripts/` — команды разработки и обслуживания.

В Git не включаются реальные `.env`, базы, переписка, вложения, сессии,
ключи, логи, резервные копии, сборки, Docker-архивы, локальные скриншоты
и инструкции администрирования конкретного сервера. `.env.example` содержит
только пустые поля и безопасные значения по умолчанию.

## Публикация и деплой

Публикация выполняется вручную по явной команде владельца: проверки, коммит,
push, затем обновление только Jorik на Synology через SSH. GitHub Actions
и отдельный CI-доступ к серверу отключены; merge в main не запускает деплой.
Файлы workflow и deploy/ci оставлены как неактивная подготовка.

Перед обновлением сохраняются compose, согласованная SQLite backup-копия
и предыдущий образ для отката. База, вложения и сессии остаются на сервере.
При ошибке возвращается предыдущая версия приложения; восстановление базы
поверх новых сообщений требует отдельного решения.

### Web Push / PWA

На HTTPS в «Настройки» → «Push-уведомления» пользователь включает уведомления
отдельно для каждого устройства. На iPhone/iPad требуется iOS/iPadOS 16.4+:
«Поделиться» → «На экран Домой», затем открыть Jorik по установленной иконке
и нажать кнопку включения. Запрос разрешения выполняется непосредственно по нажатию.
В обычной вкладке Safari iOS уведомления недоступны.

Service Worker `/sw.js` показывает уведомления и переводит в соответствующий диалог.
Переписка и API не кэшируются для офлайн-доступа. Уже открытая вкладка получает
сообщение без перезагрузки и потери черновика. При закрытом приложении открывается
ссылка `/?conversation=<id>`; при необходимости сначала потребуется вход.

Миграция 016 хранит подписки и ограниченную очередь доставки. Текущая модель Jorik
имеет одного владельца; несколько устройств привязаны к его отдельным сессиям.
Выход с устройства отзывает его подписку. Истёкшие сессии и ответы push-сервиса
404/410 удаляют подписки; временные ошибки повторяются до трёх попыток.
Входящие Telegram/Instagram уведомляют только о новых недублирующихся сообщениях;
импорт архива и собственные сообщения не создают push.

Ключи VAPID генерируются один раз в `DATA_DIR/vapid.json` с правами 600.
Файл необходимо сохранять вместе с рабочими данными и резервной копией.
Альтернатива: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` в серверном env.
Публичный ключ выдаётся только через авторизованный API, закрытый остаётся на сервере.
Не удаляйте и не перевыпускайте ключи при обычном деплое. Из-за новой runtime-зависимости
`web-push` следующий релиз требует полной сборки образа, а не прежнего code-only пакета.

Нужен исходящий HTTPS к push-сервисам Apple/Google/Mozilla/Microsoft.
Уведомления включают имя/магазин и короткий текст сообщения: ОС может показывать их
на экране блокировки. Разрешения и показ превью управляются в настройках устройства.
Готовность сервера не гарантирует мгновенную доставку ОС; реальная проверка требует
подписанного устройства. Новый push API защищён существующей авторизацией и проверкой Origin.

### Динамические шаблоны и почтовые заказы

В настройках можно добавлять, редактировать и удалять до 100 шаблонов. Сохраняется
весь массив со стабильными ID; прежние четыре слота преобразуются без потери текста
и порядка. Первые девять доступны по Ctrl+1…9. Остальные вставляются кнопкой или
через меню шаблонов. Панель в чате прокручивается горизонтально.

Тип получения «Почта» сохраняется отдельно от доставки и самовывоза. Адресные поля
для почты скрыты и очищаются сервером при сохранении. Почтовые заказы включаются
в курьерский Excel (кроме отказных), с пометкой «Почта» в колонке «Статус».
Существующие восемь колонок экспорта сохранены. SQL-миграция не требуется:
тип получения уже хранится в JSON заказа.
